# repo/workflow standards

Main-session task-lifecycle discipline for this repository.

- archive-quiescence: before archiving a task, wait for every in-flight dispatch to settle; a child that finishes after the archive move backfills against the stale pre-move path (warning only, and the record stays `running` frozen at archive time)
- effort-compat: a dispatch's `effort` must be inside the target model's supported range; an unsupported value (e.g. `low` on LongCat-2.0) produces a healthy-looking background receipt and then kills the child at its first model request with `UNSUPPORTED_REASONING_EFFORT`
- transport-failover: automatic failover is built in and single-hop — configure `fallback_models` on a role under `subagent_profiles[i].roles` (`whenMain` matches the main model; entry order is match order) and a model-access failure (`TRANSPORT`/`TIMEOUT`/`UNKNOWN_MODEL`/auth/rate-limit/quota/`UNSUPPORTED_REASONING_EFFORT`) re-dispatches once on the next chain model in a new child session, keeping the original prompt with a failover note appended, and recording the hop in `dispatches` (`fallbackOf`/`fallbackAttempt=2`); a record with `fallbackOf` set never retries (one-hop cap, hard-blocked with a reason). `rotate_on_busy: true` on the same role makes same-kind concurrent dispatches rotate the chain start (recorded as `modelSource` `rotate`); the `legacy` model source is retired and only survives as a read on old records. The manual probe below remains the fallback only when no `fallback_models` is configured or the hop is used up: when consecutive dispatches die at the first model request with `Connection error. (TRANSPORT)`, stop blind-retrying — probe a different provider route with a trivial dispatch prompt; if the probe answers, the route is the fault (not the channel), so re-dispatch on the healthy route with `force: true` and record the override; only suspect the dispatch channel itself when every route fails (observed 2026-10-21: glm and qwen routes dead while deepseek answered instantly)
- asset-version-bump: bump the `packages/core/resources/workflow/workflow.md` front-matter `version` (together with `WORKFLOW_PROTOCOL_VERSION` in `packages/core/src/injection/protocol.js`, which the handshake test pins to the real asset) only when the contract structure changes — the `states` list or the `####` step set/order; guidance-text additions inside existing steps keep both unchanged
- counter-example: bumping the front-matter version for a one-sentence guidance addition, or editing the step set without bumping version and protocol constant together
