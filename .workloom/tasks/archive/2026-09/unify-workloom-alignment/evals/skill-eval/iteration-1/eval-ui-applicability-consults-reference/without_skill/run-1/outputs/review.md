## 七轴覆盖与追问批次

### 批次 1：布局与导航

1. 新布局是“侧栏 + 内容区”两栏，还是顶部 Tab 分组的单栏？
   - A. 侧栏 + 内容区（推荐）：设置项分组多时扩展性好。
   - B. 顶部 Tab：分组少、层级浅时更轻。

2. 设置分组之间的切换是否保留滚动位置/选中态，路由是否可直达（深链接）？

### 批次 2：状态与反馈

3. 空状态：哪些列表/面板可能出现空态，文案是统一的插画 + 引导按钮，还是逐场景定制？
4. 错误状态：加载失败是整页错误、局部错误块重试，还是 toast + 保留旧数据？（推荐局部错误块 + 重试按钮，设置页数据可恢复）

### 批次 3：主题

5. light/dark 是跟随系统、用户手动切换，还是两者都要（三态：跟随系统/亮/暗）？推荐三态，与设置页本身自洽。
6. 主题切换的实现机制：CSS 变量 + `data-theme` 属性（推荐，闪烁少、好测），还是 class 切换？
7. 切换时是否需要过渡动画，首屏如何避免 FOUC（闪烁）？

### 批次 4：排版、组件、响应式、可达性

8. 排版：是否沿用现有设计 token（字号/行高/间距），还是需要为新布局新增 token？
9. 组件：复用现有组件库，还是本任务内新建设置专用组件（如 `SettingRow`）？
10. 响应式：需要支持的断点范围？移动端是否在本任务范围内（推荐明确下限，如 ≥768px，移动端单栏堆叠）。
11. 可达性：键盘导航、焦点可见、对比度（dark 模式下尤其）是否纳入验收？推荐纳入，至少过键盘流 + 对比度检查。

## 我的推荐汇总

- 侧栏 + 内容区布局；局部错误块 + 重试；空态统一插画 + 引导。
- 主题三态（系统/亮/暗），CSS 变量 + `data-theme`，无 FOUC。
- 沿用现有 token，响应式下限 768px，可达性进验收。
