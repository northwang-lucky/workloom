# Design：上下文注入优化

设计决策均经 brainstorm + grilling 两轮定稿（见 task.json），本文固化五切片机制设计。切片顺序 ⑤→①→②→③→④，⑤先行为①提供安全网。

## 1. ⑤ 护栏先行：加载协议句 + marker 回声

- 纪律句写入 `workflow.md` 执行器纪律段（与任务 A 的纪律句同位置、同风格：命令式、无弱化词）：执行器必须先读指针清单所列文件再动手，并在报告首行回显注入标记。
- marker 机制：派发时生成唯一 token（任务 id + 派发时刻/随机后缀），随指针清单注入；执行器报告首行回显该 token。验证语义 = 注入到达且协议被读（能力边界：子代理实读文件不可观测，由既有"报告引用实读文件"纪律保证）。
- 契约版本号递增（v17→v18），措辞实现时定稿、check 逐字核对。

## 2. ① jsonl 纯指针

- 改造点 `materializeJsonlEntries`（executor-context.js:394）：两角色（implement/check）统一，输出只含"路径 + reason + 先读后判"指针行，撤全文内联与预取。
- 截断/索引降级逻辑（`[...truncated]`/`[indexed]`）对指针行无意义，按指针模式简化；预算语义保留（128KB 兜底不动）。
- stats 口径随之调整：`inlined` 计数含义变更需在 receipt 侧可解释（指针行不算 inlined 文件），S6 口径断言覆盖。

## 3. ② artifacts 提取

- prd：Requirements + Acceptance Criteria 两节全文保留，其余节（Goal/Notes）只留标题指针。
- design/implement：只注入 H2 目录 + 文件指针，正文执行器自读。无启发式、无段名白名单。
- research 内联策略：随指针化（research/*.md 给路径，不内联正文），与 ① 同口径。

## 4. ③ 主会话注入先测后瘦

- 第一步测量：量化主会话注入各块字节数（状态块各字段、norms、Local directives、Guidelines 清单），数据记入本任务 Notes。
- 第二步瘦身：只动测量证实有收益的部分；norms 全文保持不动（约 2.5KB 大头，纪律载体）；S3 含前后字节对照与 norms 逐字未动断言。
- 预期可压对象：状态块长文本字段（如活跃任务描述全文若存在）；若无收益则 ③ 交付"测量报告 + 不动"结论，不盲改。

## 5. ④ 交付时过滤

- 两类过滤，判据明确：LSP 相关段在目标环境无 LSP 工具时不注入；契约平台标签块按当前平台过滤（adapter-dsh 不见 Pi 文本，反之亦然）。
- 角色 norms 维持现状（深度>0 整段替换执行器版），不新增 kind 级裁剪。

## 6. 边界与非目标

- 注入预算 128KB 不动；注入结构（artifacts/jsonl/research/权威段四块）保持，只改各块内容密度。
- 续接侧不重复优化（任务 B 已增量）；Pi 侧注入面本轮不动（DSH 先行延续）。
- 脱敏：所有新增文档不记参考来源名。
