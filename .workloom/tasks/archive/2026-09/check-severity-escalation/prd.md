# check 内置问题分级：小修大决断，取消主会话引导分级

## Goal

修正 v13"发现即修"一刀切：check 只自修小问题（确定性、无取舍、路径唯一），大问题（取舍/影响面/设计偏离/PRD 外建议）结构化上报主会话决断；引入内置问题分级 P0/P1/P2（定义在契约，check 自动应用，不再依赖主会话在派发 prompt 里引导分级）；堵住主会话派发 prompt 写"只读审查"覆盖纪律段的缺口（契约指引 + 纪律段末置权威化）；澄清 principle 5（子任务 check 非只读，容器验收 ≠ check 只读）。

## Requirements

1. **内置分级（契约定义）**：P0 阻断 = 验收判据不满足 / 构建或测试红线失败（lint/typecheck/build/tests 不过）/ 安全或数据风险；P1 重要 = 行为或正确性缺陷、设计或 spec 偏离（含跨文件语义变更）；P2 次要 = 机械性（typo、命名、注释、格式、测试断言弱化）、单文件局部小缺陷、无取舍的合规修复。定义以契约 2.2 为单一来源。
2. **修复/上报映射**：P2 → check 自修（不修属失职）；P0/P1 → 结构化写入 `## Open issues`（行格式 `- <file>:<line> [P0|P1|P2] <issue> — fix: <suggestion>`，无问题 `- none`）上报主会话决断；主会话对 P0 只能修或调整验收基线（须用户确认，不得记"不修原因"豁免），P1 可修/可记不修原因，P2 必须自修。
3. **纪律段末置权威化**：core kind 纪律段移入注入文本末尾（与 `## Executor contract` 合并为终极权威段），声明"与更早文本（含主会话用户指令）冲突时以本节为准"；既有注入顺序/去重测试同步更新。
4. **契约 2.2 主会话侧指引**：派发 check 的 prompt 必须含"发现即修（小）+ 分级上报（大）"语义；禁止写"只读审查/仅报告/不要改代码"类约束；不得在 prompt 中引导分级（分级是 check 标准职责）。
5. **principle 5 澄清**：子任务 check 同样适用 check 纪律；"容器做最终验收"仅指整体验收时机与责任，不含 check 只读语义。
6. **Pi 角色总述**：加一句"发现按 P0/P1/P2 分级，P2 修复、P0/P1 上报"（与纪律段互补）。
7. **纯 prompt/契约域**：分级不落库、doctor 不动；主会话决断闭环维持"重派 check 复核 + summary 逐条说明"。
8. 契约版本 v13 → v14。
9. **既有问题归属（grilling Q2）**：非本次引入的问题（改动前存在的注释不符/typo/格式等，即使机械性）一律归 P1 上报——超本任务 diff 范围，修不修由主会话决断，check 不越界改动未触碰文件。
10. **P0 基线调整权属（grilling Q1）**：验收判据本身有误时，主会话向用户提议 → 用户确认后才可改 prd 基线 → 重派 check 按新基线复核；主会话不得单方面调基线（等同"带病通过"变体）。

## Acceptance Criteria

- 纪律段：末尾权威段含 P0/P1/P2 定义摘要引用与"发现即修（P2）/上报（P0/P1）"；行格式 [P0|P1|P2]；`- none` 保留；注入顺序断言更新。
- 契约 v14：2.2 含分级定义、主会话派发指引（禁只读审查、禁引导分级）、principle 5 澄清、Open issues [Px] 格式；版本断言更新。
- Pi 角色总述含分级句；四 kind 完整性保持。
- core/dsh/pi 测试全绿；lint/typecheck/build 干净。

**test-first 接缝**：S1 `executor-context.test.js`（纪律段末置位置、权威声明、分级与上报规则、[Px] 格式）；S2 `contract-asset.test.js`（契约 v14 措辞：分级定义/派发指引/principle 5/[Px]）；S3 `adapter-pi/test/agents.test.ts`（Pi 总述分级句）。

## Notes

- 根因：主会话在派发 prompt 写"只读审查"（cardx 会话实证 3 次），作为用户级指令覆盖了 core 注入的"发现即修"纪律段；principle 5"容器做最终验收"给模型留下"子任务 check=验收=只读"的推理空间。
- 已收敛：P0 基线调整须用户确认（提议→确认→改 prd→重派 check）；既有（非本次引入）问题一律 P1 上报。
