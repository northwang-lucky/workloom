# 简化 workloom 人工确认流程

## Goal

减少 workloom 任务流程中的人工文档确认和内部状态管理。用户只需判断 PRD 与 PLAN 的内容是否符合意图，无需核对哈希值，也无需确认 CASE。主会话实际复核 CASE 后直接授权执行，不额外生成复核凭证。

## Requirements

- R1：PRD、PLAN、CASE 等流程文档不再要求用户确认或复述哈希值，人工确认只针对文档内容。
- R2：移除文档确认和 CASE 授权所依赖的哈希机制；PRD 与 PLAN 的确认记录只保留确认时间和文字摘要，不再通过文档哈希判断确认是否失效。
- R3：PRD 与 PLAN 分阶段确认。PRD 定稿后先确认内容，再开展后续调研和 PLAN 编写；PLAN 复核后由用户确认内容，确认后才能启动实现。
- R4：CASE 由主会话对照 PRD、PLAN 和实际代码复核；主会话满意后即可进入执行，不再等待用户确认，也不新增 CASE 复核时间、摘要或内容指纹等凭证。
- R5：除创建任务和 PRD 定稿前的持续决策外，流程中的固定人工内容确认仅限 PRD 与 PLAN。
- R6：正常任务流程、补充 CASE 流程和归档任务重建流程采用一致的文档确认规则，避免同一文档在不同入口出现不同的人工确认要求。
- R7：完整实现任务仍编写 PLAN，且 PLAN 的内容确认发生在实现开始前。
- R8：CASE 执行使用当前设计与执行会话链和实际执行结果，不再使用 CASE 文档哈希关联确认、执行结果或旧结果复用；新设计需要执行时重新运行 CASE。
- R9：主会话发现实现阻塞、需求范围变化或验收基线变化时，集中向用户提问；用户主动提出明确需求变更时，该用户消息即视为变更内容确认，主会话同步更新受影响的 PRD 或 PLAN，不要求用户再次确认同一变更。

## Acceptance Criteria

- AC1（覆盖 R1、R2）：检查 workflow、相关技能、工具参数和任务记录结构，不再存在面向用户或主会话的 PRD、PLAN、CASE 哈希确认参数；运行对应资产、核心服务和双 adapter 测试，结果通过。
- AC2（覆盖 R3、R5、R7）：按主流程完成一次 PRD 内容确认后再编写 PLAN，PLAN 内容确认前任务不能启动，确认后可以启动；除这两次内容确认外，不出现其他固定文档确认步骤。通过 workflow 结构测试与任务启动测试验证。
- AC3（覆盖 R4、R8）：在未新增用户 CASE 确认消息、未写入 CASE 复核凭证的情况下，主会话完成实际复核后能够继续同一设计会话执行 CASE；运行 CASE 服务、执行上下文及双 adapter 的相关测试，结果通过。
- AC4（覆盖 R6）：检查 `workloom-case-active` 与 `workloom-case-archived` 等入口，其说明和工具行为均不再要求用户确认 CASE 或哈希值；运行对应资产测试，结果通过。
- AC5（覆盖 R2、R8）：CASE 模板、结果校验和旧结果复用逻辑不再依赖 `caseHash`；对新设计执行 CASE 时生成新的实际结果和证据。通过核心 CASE 测试与结果模板测试验证。
- AC6（覆盖 R9）：检查 workflow 的异常决策规则，系统发现的阻塞或基线变化仍集中提问；用户主动提出明确变更时直接更新相关文档并继续，不产生第二次内容确认。通过 workflow 文本测试验证。

## Notes

- 本任务只调整人工确认与授权机制。PLAN 的伪代码编写规范由后续子任务处理；PRD 的业界格式调研与模板改造由另一个后续子任务处理。
- 本任务不涉及前端 UI，不新增 UI Design 要求。
- 已归档任务保持不可变，不直接修改归档内容。
- PRD 内容确认后如用户主动提出明确变更，主会话将该消息作为变更确认，更新受影响文档后继续；如主会话发现需求存在新的歧义，仍先集中提问。
- 不采用专门的 test-first 交付要求；通过更新现有核心、资产和双 adapter 测试保护流程行为。

## Alignment Decisions

- 已确认：创建一个容器任务和三个顺序执行的子任务；当前子任务负责人工确认机制。
- Q1 选择 A：PRD 与 PLAN 分阶段进行内容确认，PLAN 确认后再启动实现。
- Q2 选择 B：移除文档哈希机制，不再通过哈希管理文档确认或 CASE 执行授权。
- Q3 选择 B：CASE 不保留单独的主会话复核凭证，主会话实际复核后直接派发执行。
- Q4 选择 A，并附加例外：系统发现的阻塞、范围变化或验收基线变化需要集中提问；用户主动提出的明确需求变更不再二次确认。
- 已确认：正常流程、补充 CASE 和归档重建入口采用一致规则。
- 已确认：PLAN 仍是完整实现任务的必需文档，但其实现细节规范由后续子任务改造。
- 所有设计树节点均已覆盖，无剩余开放节点。
