# 新增 workloom-case-archived 技能

## Goal

提供一个主会话技能，为已归档的完整任务重建 CASE 验证。技能把历史材料作为只读参考，在当前代码基准上创建独立的新完整任务，经过正常对齐、PLAN、CASE 确认、真实执行、覆盖率和独立归档，不把结果表述为历史当时的执行证据。

## Requirements

- R1：技能仅处理 `tasks/archive/` 下已完成的 full 任务；活跃任务、未归档任务和 light 任务明确分流到其他流程。
- R2：每次调用只处理一个归档任务。未提供任务路径时列出归档 full 任务的标题、路径和归档时间，等待用户选择一个，不自动批量创建验证任务。
- R3：归档原件始终只读；处理前后计算原件全部文件的 SHA-256 清单并逐字节比较，禁止修改 task.json、PRD、PLAN、CASE、RESULT 或证据。
- R4：在当前项目创建独立 full 任务，记录 `sourceTask` 归档路径、来源提交和当前验证目的；不在归档原件上创建子任务关系。package 在当前配置中存在则继承，否则使用当前默认包；无法确定时询问用户。
- R5：历史材料按 PLAN 优先、design.md + implement.md 迁移、仅 PRD 显式标记后重建的顺序处理；只有 design 或只有 implement 的单侧材料按仅 PRD 处理并注明缺失文件，不得把缺失 PLAN 伪装成已有实施计划。
- R6：默认代码基准为当前目标分支 HEAD，也允许用户指定分支或提交；指定 commit 时先创建唯一本地分支，在用户批准后检出该分支，创建正常 worktree 后立即恢复原分支，不修改 core 的 worktree/归档逻辑。代码工作区不干净时停止切换。新任务记录解析后的完整 commit、ref 来源、选择原因和分支恢复状态，默认不把历史提交作为验证目标。
- R7：新任务重新形成 PRD 与规定式 PLAN，完成 Phase 1.1 和 1.4 用户确认后才启动；历史 CASE 与 RESULT 只能作为参考，不复用为当前通过凭据。
- R8：实施与 CASE 设计并行，check 会话先设计后执行；真实 SR/C、证据、覆盖率与标准验证遵循已交付的核心机制，无统一数值阈值。
- R9：新任务的 RESULT 明确记录当前代码基准、真实指纹、checkSession 和来源任务；历史 blocked/failed 不得直接复制为当前结论。来源提交优先取 task.commit，为空时取 `git log -1 --format=%H -- <归档路径>` 的归档记账提交并注明来源类型。
- R10：归档路径不存在、ref 无法解析、材料缺失或工作区条件不满足时停止并报告，不修改归档原件，不自动降低验收要求。
- R11：双 adapter 注册技能，Pi 构建同步副本；复用现有工具和代码指纹脚本，不新增 slash command，不改变 workflow 版本。
- R12：技能资产和评测定义使用英文，生成的任务文档遵循项目语言。
- R13：五个真实带技能场景：已有 PLAN 默认当前基准、旧 design/implement 指定 ref、仅 PRD 重建、无路径候选选择、无效输入快速失败；只报告验收是否通过与关键证据，不生成评分、benchmark 或静态审阅页。不带技能组不参与验收。
- R14：技能注册、关键文本和公开行为采用 test-first，先观察缺少技能或注册的红测试，再实现转绿。
- R15：本子任务编写符合规定式要求的 plan.md，并经 review executor 审查后启动。
- R16：新任务通过后独立提交、归档和记录日志；归档原件在处理前后保持完全一致。

## Acceptance Criteria

- AC1（覆盖 R1、R2、R11）：合法归档任务可进入技能；活跃/未归档/light 被分流；未提供路径时按确认方式处理；双 adapter 清单与 Pi 副本包含技能，无新增命令。
- AC2（覆盖 R3、R16）：准备并执行一个归档任务补验证后，原件全部文件的前后 SHA-256 清单一致；新任务独立归档，没有回写原件。
- AC3（覆盖 R4、R6）：新任务 task.json 与 CASE 的 Source task、当前完整 commit、ref 来源和验证目的准确；默认验证当前目标分支，不冒充历史执行。
- AC4（覆盖 R5）：分别用 PLAN、旧 design/implement 和仅 PRD 三类历史材料测试；PLAN 优先、旧材料迁移、仅 PRD 显式标记并重建 PLAN，结构校验通过。
- AC5（覆盖 R7）：历史 PRD/PLAN/CASE/RESULT 只读；新任务完成对齐与 1.4 确认前不启动；确认后完整生命周期可执行，旧确认 hash 不被复用。
- AC6（覆盖 R8、R9）：真实 check 会话完成 CASE 设计与执行；SR/C 全通过、真实证据与覆盖率齐全，RESULT 记录当前代码指纹和来源任务。
- AC7（覆盖 R10）：无效归档路径、不可解析 ref、缺材料和不合格工作区分别产生明确失败，无新任务启动或原件变化。
- AC8（覆盖 R11）：DSH/Pi 注册测试、Pi 构建与清单测试通过；复用现有任务/CASE/指纹工具，workflow 版本不变。
- AC9（覆盖 R12）：技能 front-matter 可解析，运行文本和评测定义为英文，任务生成物遵循项目语言。
- AC10（覆盖 R13）：五个真实带技能场景均有实际结果、验收结论和关键证据；不生成评分、benchmark 或静态审阅页，不带技能材料不参与通过判定。
- AC11（覆盖 R14）：红阶段因技能文件或注册缺失而失败；绿阶段相同测试集合通过，lint/typecheck/build 与相关包测试全绿。
- AC12（覆盖 R15）：PLAN 中每个 AC 至少在一个步骤 Covers 出现，新增文件有完整内容，计划审查无未处置 P0/P1/P2。

## Notes

- 父任务：[prd.md](../11-03-check-case-coverage/prd.md)。主流程和未归档技能已交付并归档。
- 本任务不涉及产品 UI，也不需要静态审阅页；验收只输出通过结论与关键证据，不需要 `## UI Design`。
- 不修改 `workloom-case-active` 的业务语义；共享指纹脚本可直接复用其技能资源。
- 不实现归档原件的恢复、重写或历史结果重放。
- 父任务已决定本子任务需要 PLAN，不重复询问是否编写。
- 带技能验收的五个场景有独立可交付边界，但属于同一技能的统一行为，不再拆出额外子任务。

## Alignment Decisions

- 已继承：归档原件只读、独立新任务、当前基准默认、历史材料降级顺序、完整 CASE 与覆盖率、独立归档。
- 已继承：只验收带技能组，无技能材料不参与通过判定。
- 已确认：已有历史 CASE/RESULT 只作参考，不作为当前执行凭据。
- 已确认：每个归档任务一次调用只创建一个验证任务，不批量创建。
- 已选择：未提供路径时列出归档 full 任务，由用户选择一个；每次只创建一个验证任务。
- 已确认：Source 元数据同时写入 `task.json.meta` 与 CASE 的 `Source task` 字段，两处保持一致。
- 已确认：每个场景运行 1 次；只输出验收是否通过与关键证据，不生成评分、benchmark 或静态审阅页。
- 已选择：真实验收取五个场景，增加候选选择和无效输入快速失败。
- 已选择：指定 commit 时先创建唯一本地分支，再创建可提交的正常 worktree，不扩大 core 范围。
- 已选择：task.commit 为空时使用归档路径对应的记账提交，并注明来源类型。
- 已选择：package 有效则继承，否则使用当前默认包；无法确定时询问用户；单侧旧材料按仅 PRD 处理并注明缺失文件。
- 开放节点：无。
- 收敛摘要：候选选择、原件只读、commit 落地、来源提交、材料兼容、五类真实验收和独立归档均已确定，无剩余假设。
